Modelo de datos y entorno de desarrollo

Cuatro tablas. En el prototipo cada tabla es una lista guardada en localStorage (todo el acceso está en js/datos.js), con los mismos campos que tendría una base de datos.

TablaCamposRestriccionesClave en el navegador
usuariosid, nombre, email, password, rolPK id. email único. rol = jugador o admin.padelya_usuarios
canchasid, nombre, tipo, activaPK id. tipo = Techada o Descubierta. Solo las activas se pueden reservar.padelya_canchas
reservasid, usuarioId, canchaId, fecha, horaInicio, estadoPK id. FK usuarioId y canchaId. estado = confirmada o cancelada. Única: (canchaId, fecha, horaInicio) entre las confirmadas.padelya_reservas
bloqueos (Sprint 2)id, canchaId, fecha, horaInicio, horaFin, motivoPK id. FK canchaId.todavía no se usa

La sesión no es una tabla: el id del usuario logueado va en sessionStorage (padelya_sesion), por eso se borra al cerrar la pestaña y se pueden probar dos jugadores en dos pestañas.

Relaciones

  • Un usuario tiene 0 o más reservas; cada reserva pertenece a un usuario.
  • Una cancha tiene 0 o más reservas y 0 o más bloqueos.
  • Una hora de inicio (8 a 22) dura 1 hora; el último turno empieza a las 22:00.

Equivalente en SQL (para cuando haya base de datos)

CREATE TABLE usuarios (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  nombre    TEXT NOT NULL,
  email     TEXT NOT NULL UNIQUE,
  password  TEXT NOT NULL,           -- en serio, guardar el hash
  rol       TEXT NOT NULL DEFAULT 'jugador' CHECK (rol IN ('jugador','admin'))
);

CREATE TABLE canchas (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  nombre  TEXT NOT NULL,
  tipo    TEXT NOT NULL CHECK (tipo IN ('Techada','Descubierta')),
  activa  INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE reservas (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  usuario_id  INTEGER NOT NULL REFERENCES usuarios(id),
  cancha_id   INTEGER NOT NULL REFERENCES canchas(id),
  fecha       TEXT NOT NULL,         -- AAAA-MM-DD
  hora_inicio INTEGER NOT NULL CHECK (hora_inicio BETWEEN 8 AND 22),
  estado      TEXT NOT NULL DEFAULT 'confirmada' CHECK (estado IN ('confirmada','cancelada'))
);

-- regla anti duplicados (PB-06): un solo turno confirmado por cancha, fecha y hora
CREATE UNIQUE INDEX turno_unico ON reservas (cancha_id, fecha, hora_inicio)
  WHERE estado = 'confirmada';

CREATE TABLE bloqueos (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  cancha_id   INTEGER NOT NULL REFERENCES canchas(id),
  fecha       TEXT NOT NULL,
  hora_inicio INTEGER NOT NULL,
  hora_fin    INTEGER NOT NULL,
  motivo      TEXT
);

Cómo levantarlo

  1. Clonar el repositorio (o descomprimir el zip).
  2. Abrir index.html con doble clic. No necesita servidor.
  3. Entrar con jugador@padelya.com / 123456 o crear una cuenta nueva.
  4. Para volver a los datos de prueba: "Reiniciar datos de prueba" en el pie de cualquier pantalla.

La contraseña se guarda en texto plano solo porque es un prototipo sin servidor. En un sistema real se guarda un hash calculado en el servidor.
