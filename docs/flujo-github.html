GitHub: ramas y Pull Requests

Reglas simples para que el equipo no se pise y siempre haya una versión que funciona.

Ramas

RamaQué contieneQuién escribe ahí
mainVersión estable, la que se entrega al cerrar el sprint.Nadie directo. Solo se actualiza con un Pull Request desde develop.
developIntegración del sprint: todo lo que ya fue revisado.Nadie directo. Solo se actualiza con Pull Requests desde las ramas de tarea.
feature/ITU-N-descripcionUna tarea de Jira. Ejemplo: feature/ITU-9-reservar-cancha.Quien tenga asignada la tarea.

Paso a paso para una tarea

# 1. partir siempre de develop actualizado
git checkout develop
git pull origin develop

# 2. crear la rama de la tarea
git checkout -b feature/ITU-9-reservar-cancha

# 3. trabajar y hacer commits chicos, con la clave de Jira
git add .
git commit -m "ITU-9: confirmar reserva de un turno libre"

# 4. subir la rama
git push -u origin feature/ITU-9-reservar-cancha

# 5. en GitHub: abrir un Pull Request hacia develop
#    (se completa la plantilla), pedir revisión a un compañero

# 6. con la revisión aprobada: Merge, borrar la rama y mover la tarjeta a Listo en Jira
git checkout develop
git pull origin develop

Mensajes de commit

Formato: ITU-N: qué se hizo, en presente y corto. Ejemplos: ITU-10: rechazar turnos ya reservados, ITU-5: validar email repetido.

Reglas de los Pull Requests

  • Un Pull Request por tarea, con la clave de Jira en el título.
  • Siempre hacia develop, nunca hacia main.
  • Lo revisa al menos otra persona del equipo antes del merge.
  • Antes de abrirlo: probar la pantalla en el navegador y mirar la consola (F12) sin errores.
  • Se usa "Squash and merge" para que cada tarea quede como un solo commit en develop.
  • Al cerrar el sprint: Pull Request de develop a main y una etiqueta, por ejemplo sprint-1.

Crear el repositorio

cd padelya-sprint1
git init -b main
git add .
git commit -m "Prototipo PadelYa - Sprint 1"
git remote add origin https://github.com/USUARIO/padelya.git
git push -u origin main

git checkout -b develop
git push -u origin develop

En GitHub, en Settings → Branches, proteger main y develop exigiendo Pull Request antes de mergear. El archivo .github/pull_request_template.md de este proyecto se carga solo al abrir un PR.
